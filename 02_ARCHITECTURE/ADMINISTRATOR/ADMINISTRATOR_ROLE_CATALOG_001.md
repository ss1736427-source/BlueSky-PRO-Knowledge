# ADMINISTRATOR_ROLE_CATALOG_001

## Назначение

Единый прикладной каталог ролей пользователя BlueSky PRO. Администратор выбирает пользователя по имени и назначает одну или несколько ролей. Система автоматически формирует доступные функции и рабочее меню.

## 1. Роли

### 1.1 Пилот (PILOT)

Доступ к функциям, непосредственно связанным с подготовкой, выполнением и контролем полёта в пределах предоставленного эксплуатационного контура.

Основные функции:
- подготовка и проверка полётного задания;
- работа с Flight Chart;
- контроль маршрута и профиля полёта;
- наблюдение телеметрии;
- управление разрешёнными функциями БВС;
- работа с предупреждениями и событиями;
- просмотр доступных данных миссии.

### 1.2 Техник (TECHNICIAN)

Доступ к техническому обслуживанию БВС, оборудования и технических данных в пределах назначенной области ответственности.

Основные функции:
- техническое состояние БВС;
- конфигурация установленного оборудования;
- батареи и их состояние;
- технические параметры;
- диагностика;
- обслуживание и журналирование технических операций;
- просмотр необходимых технических данных.

### 1.3 Инженер (ENGINEER)

Доступ к инженерной настройке и анализу системы в пределах назначенной области ответственности.

Основные функции:
- инженерные параметры;
- расширенная конфигурация БВС;
- правила совместимости;
- технические модели и характеристики;
- расширенные данные и диагностика;
- работа с конфигурациями CUSTOM;
- анализ и подготовка данных для инженерных задач.

### 1.4 Администратор системы (SYSTEM ADMINISTRATOR)

Полный административный контур системы.

Основные функции:
- пользователи;
- назначение ролей;
- управление доступом;
- системные настройки;
- справочники и каталоги;
- внешние подключения;
- управление данными и интеграциями;
- аудит и журнал административных действий.

## 2. Совмещение ролей

Роли не являются взаимоисключающими. Один пользователь может иметь несколько ролей.

Пример:

```text
Пользователь
├── PILOT
├── TECHNICIAN
└── ENGINEER
```

Система объединяет функции назначенных ролей без создания дополнительных учётных записей.

## 3. Правило назначения

```text
ADMINISTRATOR
    ↓
USERS
    ↓
выбор пользователя
    ↓
назначение ролей
    ↓
СОХРАНИТЬ
    ↓
автоматическое формирование доступа
    ↓
автоматическое формирование рабочего меню
```

Администратор не должен вручную собирать каждую отдельную capability для обычного назначения роли.

## 4. Интерфейс

Карточка пользователя содержит минимально необходимый набор:

```text
┌────────────────────────────────────┐
│ ПОЛЬЗОВАТЕЛЬ                       │
├────────────────────────────────────┤
│ Имя: Сергей Иванов                 │
│                                    │
│ РОЛИ                               │
│ ☑ Пилот                            │
│ ☑ Техник                           │
│ ☑ Инженер                          │
│ ☐ Администратор системы            │
│                                    │
│             [ СОХРАНИТЬ ]          │
└────────────────────────────────────┘
```

## 5. Принцип отображения

Назначение роли определяет функциональный доступ. Персональная настройка меню определяет только отображение доступных функций и не расширяет полномочия пользователя.

```text
РОЛИ
  ↓
ДОСТУПНЫЕ ФУНКЦИИ
  ↓
ДОСТУПНЫЕ ОПЕРАЦИИ
  ↓
ПЕРСОНАЛЬНОЕ МЕНЮ
```

Если функция не разрешена назначенными ролями, она не должна становиться доступной только за счёт настройки пользовательского меню.

## 6. Принцип расширения

При необходимости в будущем могут вводиться дополнительные роли, но базовая модель остаётся простой: **пользователь → роли → автоматически сформированный доступ**.
